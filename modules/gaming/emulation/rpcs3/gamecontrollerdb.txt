# SDL gamepad mappings.
#
# RPCS3 looks for this file and logs a warning when it is missing. Without it
# SDL guesses, and for the JoyMouse pad it guesses wrong: it takes the four face
# buttons in key code order and names them a, b, x, y by POSITION, which makes
# BTN_NORTH into "x" and BTN_WEST into "y". Those are the wrong way round. The
# kernel means north as the top button, x is the LEFT one, and the result was
# that triangle came out as square in the game.
#
# The entry below says it outright instead of leaving it to a guess: x is
# BTN_WEST and y is BTN_NORTH. Everything else matches what SDL worked out on
# its own, which was correct.
#
# The GUID is the bus, vendor and product the virtual pad announces, 0x1234 and
# 0x5678, so it only ever matches JoyMouse and no real hardware.
